# Design

stet is one Rust binary that keeps Gerry's Markdown knowledge repos in shape. It owns the
mechanical parts of the pattern in Workshop's
[`Meta/README.md`](https://github.com/gshaw/Workshop/blob/main/Meta/README.md); agents and
Gerry keep the judgment. Why it works this way is in [decisions.md](decisions.md).

## One shared setup, committed into each repo

Every knowledge repo runs Prettier, cspell and markdownlint-cli2, pinned by mise. Until
2026-10-03 each carried its own copy of that setup. Now the one copy is in
`src/generate.rs`, and each repo carries a generated copy:

```text
.stet.toml               what this repo does differently (stet help config)
.prettierrc.yaml         generated
.prettierignore          generated
.markdownlint-cli2.yaml  generated
.cspell.yaml             generated down to `words:`; the word list is the repo's
.mise.toml               generated down to a marker line; the tasks below are the repo's
hk.pkl                   generated: the pre-commit hook
.github/workflows/static-analysis.yml   generated, when `ci = true`
```

The copies exist because CI can't run stet: the repos are private, stet was too until
2026-11-17, and it has no release a runner could install. CI runs `mise run ci-static-analysis`, which
runs the three tools check-only on the committed configs. `stet sync` writes the copies,
and `stet check` fails with `config-sync` when one differs, so the copies can't drift
from stet or from `.stet.toml`.

Each file starts with `# Generated by stet from .stet.toml. Edit that file and run
`stet sync`.` Every ignore carries its reason as a comment, in every file it lands in.

## `stet check`

`mise run check` is still the command the AGENTS.md files and the nightly rota task use.
Its task now runs `stet check` (falling back to the bare tools when stet isn't
installed). `stet check` does, in order:

1. **Config sync**: each generated file against what `.stet.toml` makes.
2. **Prettier** rewrites Markdown in place (`--check-only` only checks, as CI does).
3. **cspell**, then **markdownlint-cli2**. One after another: run in parallel, the
   linters read files Prettier is halfway through writing.
4. **The repo's check tasks** from `[mise] check_tasks`, like Arniston's `index-check`.
5. **The house rules** (`stet help rules`): frontmatter, links and anchors, dated
   superseded blocks, and a warning for "currently" with no date nearby.

The tools run through `mise exec` in the repo, so the versions it pins are the ones used.
Their output becomes findings: file, line, column, tool, rule, severity, message. Errors
exit 1; warnings never fail. Human output lists errors and counts warnings, plus how many
files each tool read, since a green run over zero files checked nothing.

The house rules read every Markdown file the way markdownlint does, hidden folders
included, minus `.gitignore`d files, `Inbox/` and the paths `.stet.toml` ignores for
`rules`. Links resolve with exact case, one folder listing at a time, because the Mac's
file system ignores case and GitHub doesn't.

## The pre-commit hook

`hk.pkl` gives every knowledge repo a pre-commit hook. hk passes the staged Markdown
files, and the hook runs `stet check --check-only --files <them>`. The tools and rules
still read the whole repo; `--files` drops every finding outside the named files. Findings
with no file (a tool that couldn't run) and `config-sync` always count. So another
session's untracked note, or a broken file nobody is committing, never blocks a commit,
and a staged file with an unknown word always does. It takes about 3 seconds.

stet never runs git, so hk picks the files. The hook is check-only and sets
`stash = "none"`: several agent sessions share one working tree, and stashing would move
their unstaged edits off disk mid-check. The cost: a file with both staged and unstaged
edits is checked as it is on disk. A link to a file that isn't committed passes too. Both
are rare, and the full `stet check` still catches them.

`hk install --mise` turns the hook on per clone; it's git config, not a file in the repo.
`stet doctor` reads each repo's `.git/config` and `~/.gitconfig` as text and fails a repo
with no `hk-pre-commit` hook. `--no-verify` and `HK=0` skip it; that's for Gerry, and
agents are kept from it outside stet.

## `stet inbox`

The nightly mail run (a rota task) has to know two things for every repo: what's waiting
in `Inbox/`, and where mail goes. Both lived in prose it had to read five times. `stet
inbox --json` gives them as data. Items skip the Inbox's own `README.md`, `.gitignore`
and `_processed/` (Health's), which the run already ignored by hand.

The mail rules stay written in each `AGENTS.md`, where Gerry and agents edit them; stet
parses the "Mail that belongs here" section rather than moving it into config. Its
bullets are what belongs, a paragraph starting "Not here:" is what doesn't, and any other
paragraph after the bullets is a note. A repo without the section gets a `problem`, so
the run can ask rather than guess.

## `stet init`

The bootstrap steps in `Meta/README.md` as one command, into an empty folder only. It
writes everything a knowledge repo has before it has content: the configs through the same
code as `stet sync`, `.gitignore` with `Inbox/`, a `README.md`, an `AGENTS.md` with the
inbox flow, a "Mail that belongs here" section, the sensitivity never-list and the
universal rules, the `CLAUDE.md` symlink, and `Inbox/`. What only a person knows (what the
repo covers, what mail it takes, what it must never hold) is a ❌ line to fill in, so
the repo passes `stet check` from the start and an agent can find what's missing.

It runs `git init` and stops there. Creating the GitHub repo, the config entry and the
first commit are printed as next steps: they're decisions, and the first content should
be the first commit.

## `stet publish`

Workshop notes are written as publishing candidates and lifted onto gshaw.ca one at a
time, the way recipes come over from Life. `stet publish` does the copying and the checks
a person would forget; the decision to publish, the edit and the deploy stay Gerry's.

- **Refusals come first and are conservative.** A repo with `publish = false` is refused
  outright. So is a path under `never_publish`, a note still in `Inbox/`, a note that
  mentions ⚠️ publish-review, and any line that looks like a private key, an API key or
  token, a `password:`-style assignment, an account number or a card number (Luhn
  checked). A false alarm costs an edit; a miss costs a rotated key and a public page.
  The reasons give line numbers, never the secret.
- **Private links become text.** A relative link, a `file:` link, or a GitHub link into
  any configured repo (found from each repo's `origin`) would 404 publicly, so the link
  becomes its text. Images and reference definitions pointing there are dropped. Each
  change is reported by line.
- **The page is a Hugo draft:** `title` from the note's frontmatter or first `# `
  heading (which the layout prints, so it leaves the body), `date` today, `draft: true`,
  named after the note less any date prefix. stet writes the one file and prints its
  path. It never runs git and never deploys.

## Where things live

```text
~/.config/stet/config.toml   repos = [...] and [publish]; STET_CONFIG_DIR overrides
<repo>/.stet.toml            the repo's differences
~/.local/bin/stet            the installed binary (mise run publish)
```

The repo list and the publish target come from the config file, never from code, so
nothing in stet assumes `~/Documents` or `gshaw`. `stet doctor` checks all of it: mise
and the tools run (through `mise exec`, at the versions a repo pins), the config reads,
each repo exists and is in sync, and the publish target is there.

## Building

Like rota: Rust 2024 pinned in `mise.toml`, hk running rustfmt and clippy on commit, and
`mise run publish` as the whole release. It checks, tests, builds, signs the binary as
`ca.gshaw.stet` with the certificate in `ROTA_SIGN_IDENTITY` (the one set globally on
this Mac; without it, stet installs unsigned with a warning), and copies it to
`~/.local/bin/stet` through a rename.
